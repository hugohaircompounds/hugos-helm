# Release 0.4.4

Patch on top of `0.4.3`. One feature:

1. **Start/stop time tracking from the Timesheet tab** — a per-row Start/Stop button on every timesheet entry, so you can begin or end tracking a task without leaving the timesheet to go back to the task list.

Bumped via `npm version patch` → `npm run release` when ready. See [WORKFLOW.md](./WORKFLOW.md) for the full release process.

---

## Idea 1 — Start/stop time tracking from the Timesheet tab

**Today's behavior** (`src/components/TimesheetEditor.tsx`): the timesheet list is read/select-only. Each row shows the task name, its start→end window, and duration, plus a pulsing accent dot on the synthetic running row (`__running:{taskId}`). Starting or stopping a task means switching back to the Tasks tab and using `TaskList`'s controls — the timesheet can show you the running task but can't act on it.

**Goal**: each timesheet row with a real `taskId` gets its own Start/Stop button that drives the timer directly, mirroring `TaskList`'s start/stop semantics, so the timesheet becomes an actionable surface rather than a passive log.

### The approach

The row's action routes through the timer service — the single authority for timer state — not through any direct ClickUp call:

1. **`src/hooks/useTimer.ts`** already exposes `start(taskId) → window.helm.startTimer(taskId)` and `stop() → window.helm.stopTimer()`. No new IPC needed; the button reuses these.
2. **`src/App.tsx`** — thread `timer` (the `TimerState`), `onStart={(id) => start(id)}`, `onStop={() => stop()}`, and `lexicon` (theme verbs) into `<TimesheetEditor>`.
3. **`src/components/TimesheetEditor.tsx`** — `EntryRow` gains those four props and renders a Start/Stop button when `entry.taskId` is set. `e.stopPropagation()` on the click so acting on a row doesn't also change the selection.

### Running-state derivation (the key decision)

The old row split had a single `running = isRunningId(entry.id)` flag doing double duty. That was split into two distinct concepts:

- **`isSynthetic = isRunningId(entry.id)`** — drives the pulsing dot and the highlighted border. Only the synthetic `__running:{taskId}` row is "synthetic".
- **`running = timer.running && !!entry.taskId && timer.taskId === entry.taskId`** — the *authoritative* check that decides the button label/action. This reads the real timer, not the row id, so **any historical row for the currently-running task shows Stop**, exactly matching how `TaskList` decides its own start/stop state.

Button label uses the theme lexicon (`lexicon.startVerb` / `lexicon.stopVerb`); colors are `success`-toned for Start, `danger`-toned for Stop.

### Things to watch

- **Authoritative-timer check, not row-id check.** Because `running` keys off `timer.taskId`, if two timesheet rows share the same task, both correctly show Stop while that task runs. The pulsing dot still only marks the synthetic row.
- **Stop → reload → re-select is unchanged.** `App.tsx`'s existing effect reloads entries when the timer stops and re-selects the matching real entry by `taskId`; starting/stopping from a row rides the same path.
- **Synthetic rows have no `taskId`? They do.** The synthetic running entry carries the real `taskId`, so its button renders as Stop — redundant with the dot but consistent.
- **Row click vs. button click.** The button stops propagation; clicking anywhere else on the row still selects it for editing.

### What changed

| Path | Change |
|---|---|
| `src/components/TimesheetEditor.tsx` | `Props` and `EntryRow` gain `timer` / `onStart` / `onStop` / `lexicon`. Split `running` into `isSynthetic` (dot + border) and `running` (authoritative timer match). Row becomes a flex layout with a right-aligned Start/Stop button, shown when `entry.taskId` is set. |
| `src/App.tsx` | Pass `timer`, `onStart={(id) => start(id)}`, `onStop={() => stop()}`, and `lexicon` into `<TimesheetEditor>`. |

## Verification

- [ ] Timesheet tab: every row with a real task shows a Start button when idle.
- [ ] Click Start on a historical row → that task's timer starts; a synthetic running row with the pulsing dot appears; ClickUp web confirms an in-progress entry within ~1s.
- [ ] The running task's row(s) flip to a red Stop button.
- [ ] Click Stop → the timer stops; ClickUp web confirms; the row reverts to Start.
- [ ] Two historical rows for the same task both show Stop while that task is running (authoritative-timer check).
- [ ] Button labels reflect the active theme lexicon (`startVerb` / `stopVerb`).
